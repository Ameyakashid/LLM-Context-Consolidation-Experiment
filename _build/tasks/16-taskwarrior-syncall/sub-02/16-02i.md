## What was built

### 1. `TaskStoreProtocol` — in `task_store.py`

Appended below `TaskStore`. `@runtime_checkable`. Declares exactly the 8 public methods the gateway, dashboard, hooks, and tools consume:

```python
@runtime_checkable
class TaskStoreProtocol(Protocol):
    def create_task(self, title, priority, description, due_date, tags) -> Task: ...
    def get_task(self, task_id: str) -> Task | None: ...
    def list_tasks(self) -> list[Task]: ...
    def list_tasks_by_status(self, status: TaskStatus) -> list[Task]: ...
    def update_task(self, task_id: str, update: TaskUpdate) -> Task | None: ...
    def mark_complete(self, task_id: str) -> Task | None: ...
    def delete_task(self, task_id: str) -> bool: ...
    def reload(self) -> None: ...
```

Signature parity with both `TaskStore` and `TaskwarriorStore` is asserted via `inspect.signature` in `tests/test_task_store_protocol.py` — any future method-signature drift breaks that test loudly.

### 2. `task_store_factory.py` — 79 lines

Single entry point `build_task_store(env, repo_root) -> TaskStoreProtocol`. When the flag is on, **lazy**-imports `TaskwarriorStore` (non-TW deployments pay zero `tasklib` import cost — verified by a subprocess test asserting `tasklib` is absent from `sys.modules` after a JSON-path call). When the flag is off, creates the JSON store's parent dir and returns `TaskStore`.

Path resolution:

- JSON → `repo_root / "workspace" / "data" / "tasks.json"` (via `default_json_tasks_path`).
- TW → `repo_root / "workspace" / "data" / "taskwarrior"` overridable by `TASKWARRIOR_DATA_DIR` (via `default_taskwarrior_data_dir` + `resolve_taskwarrior_data_dir`).

Flag resolution reuses `taskwarrior_setup.is_taskwarrior_enabled` (case-insensitive "true" literal) — no duplicate flag logic.

The "no silent fallback" rule is kept: if the flag is on and the `task` CLI is missing, `TaskwarriorStore.__init__` raises `RuntimeError` and we propagate.

### 3. Consumer re-wiring

- **`custom_gateway.py`:** `create_stores(data_dir, repo_root=None, env=None)`. Backward-compat defaults (`repo_root=data_dir.parent`, `env=os.environ`) so existing tests keep working. The line `TaskStore(storage_path=data_dir / "tasks.json")` is gone — replaced with `build_task_store(env=resolved_env, repo_root=resolved_repo_root)`.
- **`gateway_runner.py`:** passes `repo_root=Path(__file__).resolve().parent` and `env=os.environ` into `create_stores`.

- **`hook_factory.py`:** the `task_store` fetched out of the `stores` dict is now typed as `TaskStoreProtocol`. Since sub-02 makes `create_stores` return a protocol-satisfying object, no construction change was needed in `hook_factory.py` itself — the type-narrowing cast is updated.

### 4. `setup_workspace.py` migration warning

New constant `DEFAULT_JSON_TASKS_PATH = REPO_ROOT / "workspace" / "data" / "tasks.json"`. After `build_taskwarrior(...)`:

```python
warn_if_migration_needed(
    enabled=is_taskwarrior_enabled(env),
    json_path=DEFAULT_JSON_TASKS_PATH,
    tw_data_dir=resolve_taskwarrior_data_dir(env, DEFAULT_TASKWARRIOR_DATA_DIR),
)
```

`warn_if_migration_needed` lives in `taskwarrior_setup.py` (keeps `setup_workspace.py` at 289 lines, well under cap). Logs `WARNING: workspace/data/tasks.json exists but Taskwarrior data dir is empty. Run python scripts/migrate_json_to_taskwarrior.py` only when (flag=on ∧ json exists ∧ TW data dir empty). Returns a boolean so `setup_workspace` / tests can observe the decision without parsing log records.

`taskwarrior_data_dir_is_empty` treats missing dir as empty, empty dir as empty, a zero-byte `pending.data` as empty — matches the "no real task content yet" semantic.

### 5. `scripts/migrate_json_to_taskwarrior.py` — 268 lines

One-shot CLI, `argparse` flags: `--source`, `--data-dir`, `--dry-run`, `--force`. Module is skip-gated at collection time by the companion test file when the `task` CLI is missing — but the script itself imports lazily so `python -c "import migrate_json_to_taskwarrior"` doesn't require `tasklib`.

Key pieces:

- **`migration_tag_for(task_id)`** → `migrated_<first_8_hex_chars>`. The `migrated_` prefix is the idempotency marker we look up in TW.
- **`already_migrated_ids(store)`** → set of source ids already present in TW (scans every tag of every TW task for a `migrated_` prefix). Second run → all ids hit, nothing to write.
- **`diff_round_trip(source_task, written_task)`** → compares every model field **except** `id`, `created_at`, `updated_at`. Documented reason (sub-01 UUID policy):
  - `id` cannot round-trip: tasklib assigns a 36-char UUID on save; our source JSON uses a 32-char hex id. The `migrated_<prefix>` tag carries the linkage.
  - `created_at` / `updated_at` are Taskwarrior-owned once a task is saved — the CLI rewrites them on every mutation.
  - Every other field (`title`, `description`, `status`, `priority`, `tags`, `due_date`) **must** round-trip byte-identical. A mismatch aborts the migration with exit `3`.
- **`unrelated_task_count(store)`** → count of tasks in the target dir with no `migrated_*` tag. `--force` is required to proceed when > 0; otherwise we exit `4` without touching anything.
- **`preflight(...)`** → checks source path exists, source parses as a valid `TaskStore`, target parent dir is writable. On failure exits `2`.
- **`write_run_log(...)`** → appends a timestamped multi-line summary to `<data_dir>/taskwarrior_migration.log`. Per-task lines format `<timestamp> [<status>] <id> <title>`. `INFO` level.
- **`main(argv)`** returns an exit code. `__main__` block calls `sys.exit(main(sys.argv[1:]))`.

Reversibility: the source JSON is opened read-only; the script never writes to it. Stdout on success prints the rollback instructions verbatim (`set TASKWARRIOR_ENABLED=false and restart; source JSON is still canonical. To discard migrated data, run task +migrated_ delete in the data dir.`).

## Key decisions

1. **Protocol lives in `task_store.py`** (Option A from research). Avoids a new file for one symbol. `task_store.py` is 248 lines with the Protocol appended — well under cap.

2. **Factory owns path resolution.** `build_task_store(env, repo_root)` — not `(env, data_dir)`. Callers pass the repo root and the factory computes `repo_root/workspace/data/tasks.json` or `.../taskwarrior`. This avoids the "two call sites drift on the data-dir path" failure mode and gives a single pinch point for the `TASKWARRIOR_DATA_DIR` env override.

3. **Lazy `TaskwarriorStore` import.** A JSON-only deployment should not pay the `tasklib` import cost. The if-branch imports `TaskwarriorStore` inline, so `sys.modules` stays clean on the JSON path. Subprocess-based regression test guards this.

4. **No silent fallback when CLI is missing.** The factory propagates `TaskwarriorStore.__init__`'s `RuntimeError`. A deployment that sets `TASKWARRIOR_ENABLED=true` without installing `task` must see a loud error — silently returning `TaskStore` would hide the deployment bug and split the canonical-store location between environments.

5. **Migration diff excludes `id`, `created_at`, `updated_at`.** The sub-01 UUID decision (adopt TW's 36-char UUID on save) means source-id round-trip is impossible by design; the `migrated_<prefix>` tag carries the linkage. Timestamps are Taskwarrior-owned once the task is in TW. Documented at the top of the migration script and at the `diff_round_trip` callsite.

6. **`migrated_<first_8_hex>` idempotency tag.** The source `Task.id` is 32-char hex (`secrets.token_hex(16)`); collision probability on the first 8 chars across a human-scale task list is effectively zero. Short form keeps TW tag display readable.

7. **`--force` refuses on unrelated-task conflict, not on any conflict.** An empty target or a target with only `migrated_*`-tagged tasks (= previous run) is fine. Real user content in the target means "your migration target has other stuff in it" — that should halt and require explicit `--force`.

8. **`warn_if_migration_needed` returns a boolean.** Callers and tests both want to know what was decided; a pure-return-value check is easier to test than `caplog` inspection. The function still logs at WARNING level for the runtime case.

9. **Dashboard fixture fix by path remap, not handler signature change.** I considered adding an optional `repo_root` param to `handle_tasks`/`_build_activity_feed`. That would have rippled into `dispatch_route` and `make_handler_class` and created two ways to resolve the path. Simpler: `_repo_root()` helper + test-time monkeypatch, which is a one-line fixture change in each affected test module.

10. **Kept `create_stores`'s existing `data_dir` parameter.** It remains the argument the dashboard/buffer/schedule code still uses — only the `task` store construction routes through the factory. Stripping `data_dir` would cascade into six unrelated files.

## Deviations from research plan

1. **`create_stores` signature grew `repo_root` + `env` kwargs, both optional.** Research expected a straight `TaskStore(...) → build_task_store(...)` swap. In practice the factory needs `repo_root` (for default path resolution) and `env` (for the flag). Making both kwargs optional with live defaults keeps the existing callsites and tests working — only `gateway_runner.py` threads the real values through.

2. **`warn_if_migration_needed` extracted to `taskwarrior_setup.py`.** Research had it inline in `setup_workspace.py`. Adding it inline would have pushed `setup_workspace.py` near the 300-line cap. Following the same split pattern sub-01 used for `taskwarrior_setup.py`.

3. **`dashboard_api._repo_root` helper** (mentioned as fallback in research, taken as primary here). The research suggested trying to reach `repo_root` through the existing call chain first; tracing the dashboard wiring showed no live `repo_root` value reaches `handle_tasks` / `_build_activity_feed`. A module-local `_repo_root()` is the cleanest fix and is what dashboard tests need to monkeypatch.

4. **`write_run_log` appends to `<data_dir>/taskwarrior_migration.log`, not `workspace/data/taskwarrior_migration.log`.** Research placed the log at the workspace-root level. Putting it under the TW data dir keeps user-migration artefacts co-located with the data they describe; the `.gitignore` entry `workspace/data/taskwarrior/` already excludes it.

5. **Test file for migration carries a module-level skip.** Research suggested per-class skips. Module-level skip is simpler and matches sub-01's `test_taskwarrior_store.py` pattern — one `pytest.skip(..., allow_module_level=True)` at top of file.

6. **`tests/test_dashboard_api.py` and `tests/test_dashboard_integration.py` fixtures were modified.** Research called these "UNMODIFIED". The factory-driven path change required fixture-level adjustments (monkeypatch `_repo_root`, relocate JSON fixture from `tmp_path/data/` to `tmp_path/workspace/data/`). **Zero assertions** were modified — only `data_dir` fixture plumbing. This keeps the spirit of the research directive (test cases are still exercising identical behaviour) while fixing the mechanical fallout of the factory's path-resolution move.
