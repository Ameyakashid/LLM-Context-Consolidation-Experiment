## Key decisions

### 1. SOUL.md placement: between `## Fire Tablet Display` and `## Calendar` (not literally between `## Calendar` and `## Fire Tablet Display` as the description stated)

The description says "insert between `## Calendar` and `## Fire Tablet Display`", but the live SOUL.md order is `## Fire Tablet Display` (line 270) → `## Calendar` (line 279). Research 16-04r.md §1d and §4a called out this mismatch and proposed two non-regressing options:

- **(a) Insert between `## Fire Tablet Display` and `## Calendar` — chosen.** The two sections are already adjacent in the live file; this places the new section between them without reordering anything. AC #2 ("Other sections are unchanged, byte-identical diff outside the insertion range") is satisfied.
- Rejected (b) After `## Calendar`. Also non-regressing, but "between" them would be false in both literal and spirit since any other section would sit between the pair.
- Rejected (literal reading): reordering `## Fire Tablet Display` and `## Calendar` to match the description's order would violate AC #2 hard.

### 2. Integration test approach: real Taskwarrior binary + tmp data dir (Approach A)

Research 16-04r.md §3a weighed mock vs. real binary. Chose real binary because the point of the integration suite is to prove the consumer chain trusts the factory + backend swap end-to-end — mocking `build_task_store` would only re-prove what sub-02's `test_task_store_factory.py` already locks, not that Taskwarrior actually serves correct data through the three consumer paths. Module-level `pytest.skip(..., allow_module_level=True)` when `shutil.which("task") is None` keeps CI green on boxes without the binary.

### 3. Divergence warning is a doc artefact

Research 16-04r.md §4f: sub-04 scope forbids adding a reconcile tool. The warning lives in `TASKWARRIOR.md`'s Rollback section in three forms: a bold "Divergence warning." sub-heading, the explicit sentence "Do not flip-flop the flag", and the imperative "Pick a backend and stay there". The deploy test asserts the warning's prominence so a verify agent grep can confirm it is still there.

### 4. Test layout: 5 files, 30 tests, topic-isolated

Description suggested 5 test files with 25–35 tests total. Final count: 6 + 5 + 6 + 11 + 2 = 30. Split kept each file small and single-purpose (deploy byte-identity in one file, SOUL placement in another, rollback safety in a third, consumer paths in the integration suite, and the one-way MagicMirror-switch proof isolated). No file approaches the 300-line cap.

### 5. `TaskUpdate` kwargs via **-expansion stays as is

Research 16-04r.md §4b flagged pre-existing mypy complaints in `task_tools.py` (30+ errors). Sub-04 scope says these are sub-02 LOWs that sub-04 must surface, not absorb. Verified: `mypy --strict task_store.py setup_workspace.py` is clean. The integration suite imports `task_tools` transitively; the suite's own source is mypy-strict clean (zero errors in the 5 new test files).
