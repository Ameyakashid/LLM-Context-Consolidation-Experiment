## What was built

### 1. `magicmirror_hook.py` — 289 lines

A single `MagicMirrorHook` class plus seven small pure helpers
(`build_webhook_base_url`, `is_checkin_missed`,
`format_state_change_message`, `format_buffer_alert_message`,
`format_missed_checkin_message`, `should_log_error`,
`collect_alertable_buffers`).

Lifecycle: `before_iteration(context)` is the nanobot entrypoint. It
gates on `is_scheduled_session()` (heartbeat-only; zero cost in chat
turns), then runs four steps in sequence — `_dispatch_state_change`,
`_dispatch_buffer_alerts`, `_dispatch_missed_checkins`, `_refresh_feeds` —
and catches any escaping exception with a rate-limited WARNING so a
broken hook cannot crash the agent loop.

Dedup is in-memory only:
- `_last_dispatched_state: StateName | None` — state transitions dispatch
  exactly once; the first tick primes the value without sending.
- `_buffer_dispatched: set[tuple[str, date]]` — per-day, keyed on buffer
  name.
- `_missed_dispatched: set[tuple[str, date]]` — per-day, keyed on
  `type_id`.

After a restart these reset; a single duplicate alert is the accepted
tradeoff for avoiding disk-backed dedup.

Missed-check-in detection lives in a new pure predicate
`is_checkin_missed(entry, current_date, current_datetime)` because the
sub-02 schedule engine is blind to missed entries (it only reports
"due"). The predicate strips tz from `current_datetime` before
combining with the naive `entry.target_time`, matching the convention
established in `render_schedule_markdown`.

All webhook sends route through `send_alert_async` (fire-and-forget,
backed by sub-02's `ThreadPoolExecutor`). Feed refresh calls
`write_feeds` which writes all three files atomically via tmp+rename.
Both paths are exception-swallowed through `_log_error`, which is
rate-limited to 1 WARNING per hour per hook instance via
`should_log_error`.

### 2. `hook_factory.py` — 260 lines (extracted)

After wiring the MagicMirror branch, `custom_gateway.py` crossed the
300-line cap. The hook-chain build was factored into a standalone
module. `hook_factory.py` owns:
- `HOOK_CHAIN_ORDER`, `DISCO_HOOK_NAME`,
  `DEFAULT_DISCO_VOICES_FILENAME`, `DEFAULT_MAX_MEMORY_ENTRIES`
- `SessionFlag`, `LLMCallableWrapper`
- `create_hooks(...)` — now accepts `repo_root: Path | None` and
  `env: Mapping[str, str] | None` and appends `MagicMirrorHook` after

`custom_gateway.py` now re-exports the chain symbols for back-compat
(external callers import from `custom_gateway`) and retains only the
store/tool surface: `resolve_data_dir`, `resolve_states_path`,
`create_stores`, `register_all_tools`, `register_voice_tools_deferred`.
Final size: 137 lines.

## Decisions and deviations from the research plan

**Buffer-alert source: structured store read, not prompt scraping.**
15-03r.md flagged this as an implementation-agent choice. I chose the
structured read (`buffer_store.list_active_buffers()`) because (a) it
removes BufferHook-prompt-format coupling, (b) scraping would tie the
hook to prompt text that is subject to change, (c) the store access is
cheap and already the source of truth.

**Missed-check-in detection via new pure predicate.** The research
plan called this out explicitly — `schedule_engine`'s
`is_checkin_due` filters missed entries out; `is_checkin_missed`
detects exactly those. Signature mirrors `is_checkin_due` for
symmetry: `(entry, current_date, current_datetime) -> bool`.

**Hook-chain refactor extracted.** Research didn't prescribe this; it
fell out of the 300-line cap check after wiring MagicMirror into
`custom_gateway.create_hooks`. Done as a one-shot move rather than a
gradual API shift — `custom_gateway` still re-exports the five names
external callers use (`SessionFlag`, `LLMCallableWrapper`,
`create_hooks`, `HOOK_CHAIN_ORDER`, `DISCO_HOOK_NAME`).

**Feed renderers called per-heartbeat, not per-state-change.** The
plan recommended this for simplicity; I kept it. One unconditional
refresh per tick costs ~a few KB of atomic writes; detecting
"something changed" would duplicate store state and add a new cache
invariant.
