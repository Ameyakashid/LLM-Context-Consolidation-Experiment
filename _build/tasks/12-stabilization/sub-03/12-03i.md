### `custom_gateway.py` — Parts B (count) and C (docstring)

**Part B:** `register_all_tools` now computes its return by summing each per-registrar return value rather than returning a hardcoded literal. The docstring no longer asserts a specific integer.

```python
return (
    register_task_tools(registry, task_store)
    + register_buffer_tools(registry, buffer_store)
    + register_memory_tools(registry, memory_store)
)
```

The three temporary `task_store` / `buffer_store` / `memory_store` local bindings are kept because they carry `# type: ignore[assignment]` narrowing from the `dict[str, object]` stores parameter — inlining the casts into the sum expression would duplicate the ignore comments.

**Part C:** `create_hooks` docstring changed from `"Create all 6 hooks in chain order."` to `"Create the hook chain: 5 base hooks plus an optional DiscoHook."` with a second sentence explaining that DiscoHook is appended only when `disco_voices.yaml` exists and parses cleanly. The module-level `HOOK_CHAIN_ORDER` constant (5 names) and the separate `DISCO_HOOK_NAME` constant remain truthful under this phrasing.

### `hook_adapter.py` — Part D

Added a single `#` comment above the `try:` on the `before_iteration` delegation:

```python
# Swallow per-hook failures so one broken hook cannot crash the agent loop.
try:
    await self._hook.before_iteration(context)
except Exception:
    log.exception("Hook %s.before_iteration failed", self._name)
```

The behavior is unchanged — no circuit-breaker, no re-raise. Research noted that in-repo precedent puts WHY in `log.exception` message strings rather than in `#` comments; the description explicitly asked for a `#` comment, so I followed the description. The wording is from the audit's suggested phrasing.

### `task_tools.py`, `buffer_tools.py`, `memory_tools.py`, `voice_tools.py` — Part B signature update

Each `register_*_tools` function now:

1. Returns `int` (count of tools registered) instead of `None`.
2. Builds a `list[Tool]` of instances, iterates to register them, then returns `len(tools)`.
3. Logs the count using `%d` formatting, so the log message stays truthful if a tool is added later.

Example (`task_tools.py`):

```python
def register_task_tools(registry: ToolRegistry, store: TaskStore) -> int:
    tools: list[Tool] = [
        CreateTaskTool(store=store),
        ListTasksTool(store=store),
        GetTaskTool(store=store),
        UpdateTaskTool(store=store),
        CompleteTaskTool(store=store),
    ]
    for tool in tools:
        registry.register(tool)
    count = len(tools)
    log.info("Registered %d task tools: create, list, get, update, complete", count)
    return count
```

Why a `list[Tool]` instead of leaving the five `registry.register(...)` calls inline: once the count needs to be computed rather than hardcoded, the list eliminates the duplicate literal in the log message. All four registrars follow the same shape, which aligns them with the existing `register_voice_tools_deferred` (which already returned `int`).

## Key decisions

1. **Option A for code-rules (drop line 58, drop the parenthetical):** collapses to exactly one rule in the Universal section where all default-parameter guidance already lives. Options B and C left two physical statements in the file, weakening the acceptance criterion.

2. **List-based registration inside each registrar:** once the count is dynamic, the cleanest pure-function shape is `build list → register each → return len`. This removes the duplicate literal from the log message (so the `%d` in the log line is truthful by construction) and keeps each registrar under 15 lines. Not an abstraction — same cost as the previous flat sequence, plus one `len()` call.

3. **Kept the temporary store bindings in `register_all_tools`:** the bindings exist to carry the `# type: ignore[assignment]` narrowings from `dict[str, object]` to the specific store types. Inlining them into the sum expression would duplicate the ignore comments on each call site.

4. **WHY comment above the `try:`, not above the `except:`:** the comment states the intent of the entire try/except block, not just the exception-handling branch. The audit's proposed wording frames this as a design choice about the whole adapter ("swallow per-hook failures") rather than just about the log call.

5. **Per-registrar test updates, not only the aggregate:** each `register_*_tools` test now asserts its return count matches its registry-side count. This means a future regression that breaks the count plumbing (e.g. someone forgets to `+ 1` when adding a tool) is caught at the per-registrar level, not only in the aggregate `register_all_tools` test.
