## Files Created

### `voice_input_integration.py` (262 lines, mypy --strict clean)

Module that monkey-patches each chat channel's `transcribe_audio` method at gateway startup. Public surface:

- `setup_voice_input(env, channels, *, backend_builder=None) -> int` — single entry point. Flag-gated on `VOICE_INPUT_ENABLED=true`. Returns count of patched channels (0 when OFF). `backend_builder` is a test seam; production passes `None` and the module defaults to `transcription_backend.build_transcription_backend`.
- `is_voice_input_enabled(env)` — strict `== "true"` check, mirroring `pulse_checkin_store.is_pulse_engine_enabled` idiom.
- `resolve_max_voice_duration(env)` — reads `MAX_VOICE_DURATION_SECONDS`, default 180, clamps to `>= 1`, raises `ValueError` on non-integer.
- `render_transcription_text(result, threshold)` — collapses internal whitespace; prefixes `(low confidence) ` when `is_low_confidence` returns True.
- `estimate_audio_duration_seconds(path)` — `st_size / 2048` heuristic (≈ 16 kbps OGG Opus). Returns `None` when file missing or zero bytes; `None` callers must NOT reject.
- `install_voice_transcription(channels, backend, max_duration, threshold, clock=None)` — per-instance `setattr` swap. Skips channels lacking `transcribe_audio`.

Module constants:
- `LOW_CONFIDENCE_PREFIX = "(low confidence) "`
- `FAILED_MARKER = "failed to process voice message"` — non-empty so upstream `_download_message_media` wraps it as `[transcription: failed to process voice message]` rather than dropping to `[voice: /path]`.
- `OVER_DURATION_MARKER_TEMPLATE = "voice too long — limit {seconds}s"`
- `VOICE_BYTES_PER_SECOND = 2048`
- `ERROR_LOG_INTERVAL = timedelta(hours=1)`

The patched closure (`_build_patched_transcribe`) catches **only** the four sub-01 exceptions: `FileNotFoundError`, `RuntimeError`, `httpx.RequestError`, `httpx.HTTPStatusError`. Anything else (notably `asyncio.CancelledError`) propagates. WARN logs are rate-limited to 1/hr per channel via module-level `_last_error_log_at: dict[str, datetime]`, with `_reset_rate_limit_state()` exposed as a test seam.

## Key Decisions

- **Per-instance attribute monkey-patch over subclass.** `setattr(channel, "transcribe_audio", new_fn)` lands on the instance `__dict__` and shadows the class method. Python attribute lookup resolves the instance binding first, and instance-attribute callables don't auto-prepend `self` (no descriptor protocol invocation), so the closure receives `(file_path)` cleanly. A subclass-based override would have required reaching into nanobot's `ChannelManager` factory and changing class registration — far more invasive and brittle if upstream renames the base.
- **Module-level rate-limit state with test seam.** A `dict[str, datetime]` keyed by channel name plus `_reset_rate_limit_state()` matches the pattern used by `magicmirror_hook` and lets the suite isolate tests without monkey-patching `time.time`.
- **`VOICE_BYTES_PER_SECOND = 2048` (≈ 16 kbps).** Telegram OGG Opus voice notes hover at 16 kbps; choosing the floor of that range biases the heuristic toward over-estimating duration, which means borderline files may be rejected rather than admitted past the cap. The research plan explicitly preferred this skew over importing mutagen for two more accurate digits.
- **`resolve_max_voice_duration` clamps, doesn't raise, on values below 1.** Operator setting `0` or `-5` is treated as a typo for "use the minimum" rather than a hard boot failure. Non-integer values still raise — that's a config-format error, not a magnitude error.
- **Default `backend_builder=None` resolves to `build_transcription_backend` lazily** so importing `voice_input_integration` does NOT eagerly drag the sub-01 factory's transitive imports into `sys.modules`. The flag-OFF subprocess probe verifies `faster_whisper` stays out of the module table.
- **Catch list is exactly the four sub-01 exceptions.** `FileNotFoundError`, `RuntimeError`, `httpx.RequestError`, `httpx.HTTPStatusError`. `httpx.HTTPStatusError` is NOT a subclass of `httpx.RequestError`, so both must be listed explicitly. `asyncio.CancelledError` is excluded so shutdown signals propagate.
