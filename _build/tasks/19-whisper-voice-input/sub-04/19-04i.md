## Files created

### `tests/fixtures/audio/hello_world.wav` (binary, 48 044 bytes)

1.5 s of zero-PCM samples, mono 16-bit 16 kHz. Generated by
`scripts/generate_voice_fixture.py --mode=silent` (the default). Sits
under the description's 50 KB cap (48 044 < 50 000) without trimming
sample rate or sample width.

### `scripts/generate_voice_fixture.py` (~120 lines)

One-shot, gated on `__name__ == "__main__"`. Two modes:

- `--mode=silent` (default): writes the silent WAV via stdlib `wave`.
  This is the path used to generate the committed fixture.
- `--mode=kokoro`: synthesises arbitrary text via the project's existing
  `tts_engine.synthesize_speech`, then resamples 24 kHz → 16 kHz via a
  stdlib decimating averager (3-in / 2-out). Documented but not run in
  CI; the Kokoro model files are not on the build host.

The script enforces the 50 KB cap at write-time (`SystemExit` if
exceeded) so any future regeneration that drifts above the cap fails
loud rather than silently shipping an oversized fixture.

### `workspace/VOICE_INPUT.md` (108 lines)

User-facing runbook mirroring the structure of `MAC_DEPLOYMENT.md` /
`INSTALL_MAC.md`. Eight required sections: TL;DR, How It Works,
Backends (table with `local` / `openai` / `groq` rows including env
var, cost/min, privacy, latency), Switching Backends (5 steps), When
Transcription Is Wrong, When It's Silent (troubleshooting table),
Privacy (per-backend), Cost (ties to the `$7/month` ceiling).

Vendor privacy quotes are sourced inline by URL with the retrieval
date (2026-04-20) noted under the table — this lets a future reader
confirm policy drift instead of trusting a stale quote.

### `tests/test_voice_input_e2e.py` (~250 lines)

The seven test functions from AC #1, kept as module-level functions to

1. `test_local_backend_transcribes_fixture` — runs the real

3. `test_install_voice_transcription_replaces_transcribe_audio` —
   real `install_voice_transcription` against a `_StubChannel`; the
   committed fixture flows through and the recording backend confirms
   the path argument matches.
4. `test_low_confidence_prefix_round_trip_through_channel` — backend
   returns `confidence=0.2`; patched method returns
   `"(low confidence) maybe hello"`; the e2e assembles the

5. `test_e2e_path_with_soul_md_section_present` — reads `workspace/SOUL.md`

7. `test_backend_exception_returns_failed_marker` — `_RaisingBackend`

## Key decisions

### Fixture path: silent stdlib WAV (Approach A1 from research)

The research listed three options; A1 (silent stdlib `wave`) was the
only one that respected the description's ≤50 KB cap without trimming
quality (1.5 s × 16 kHz × 16-bit mono = 48 044 bytes including the
44-byte WAV header). Kokoro TTS (A2) requires the 330 MB model which
is not present on the build host, and a real "hello world" Kokoro
clip at 16 kHz mono 16-bit measures ≈ 64 KB — over cap. The
description explicitly sanctioned this fallback ("the implementer may
use Python's `wave` module to emit a silent 2-second WAV and adjust
the test… assert result.text is empty string OR confidence ≤ 0.3").

To preserve AC #1's literal test name `test_local_backend_transcribes_fixture`
(rather than the renamed `_silent_fixture` variant), the test
assertion is an OR: empty + low confidence (silent fixture path) OR
substring `"hello"` (real-speech path). Either fixture shape passes
without renaming the test, which keeps the door open for a future
contributor to regenerate the fixture via `--mode=kokoro` without a
test edit.

Empirical check: the local backend on the build host (faster-whisper
0.9.0 with `vad_filter=True`) returns `text=""`, `confidence=0.0`
against the silent fixture — the OR branch hits cleanly.

### TEMPLATE_FILES slot: after `DASHBOARD.md`

The research correctly noted the manifest is thematically grouped, not
alphabetical, so the description's "between SYNCALL.md and USER.md"
anchor is inaccurate. I placed `VOICE_INPUT.md` immediately after
`DASHBOARD.md` because:

- Both are user-facing surface docs (how the user interacts with the
  bot through a particular channel/feature).
- `DASHBOARD.md` is the closest existing sibling — the runbook reads
  to a similar audience.
- The Mac runbook block (`INSTALL_MAC.md` … `MAC_DEPLOYMENT.md`) sits
  immediately above and is deployment-focused, not feature-focused —
  putting VOICE_INPUT.md inside that block would mis-categorise it.
- Insertion at this slot keeps the trailing nested entries
  (`disco_voices.yaml`, `memory/MEMORY.md`, `templates/DREAM.md`) in
  their existing positions.

### Over-duration test: large tmp byte file (Option E1)

The pure-tests file (`test_voice_input_integration_pure.py`) uses
`_make_audio(size_bytes=VOICE_BYTES_PER_SECOND * 200)` — same shape.
E1 keeps the production `MAX_VOICE_DURATION_SECONDS` default in the
test surface, which the verification check #10 explicitly listed as
acceptable. E2 (tiny `max_duration` override) would have been cheaper
but would not exercise the production cap.

### Faster-whisper gating: `pytest.importorskip` + fixture guard

The build environment's system Python has faster-whisper 0.9.0; the
project venv (the one `pytest` runs under) does not. Either way the
test skips cleanly if the import is missing. Using `importorskip`
keeps the gate at the top of the test, before the model construction,
so a missing-dep failure mode never leaks into the test body. The
fixture-existence guard is a separate `pytest.skip(...)` so a missing
fixture is reported with its path rather than masquerading as an
import failure.

### Hosted-backend test: factory-vs-direct contract assertion

Description called for "asserts the `render_transcription_text`
output is identical whether content hit the Whisper API or the mock
(contract stability)". I implemented this by constructing one backend
through `build_transcription_backend({"TRANSCRIPTION_BACKEND":
"openai", ...})` and another directly, asserting the factory yields
the right concrete type, then exercising the direct one (because the
factory-built one cannot accept a `transport` injection). This
preserves the contract spirit (production path uses the factory; test
path proves the factory builds the right class) without inventing a
factory-internal mocking seam.

## Mac-deferred live smoke

Per AC #11: the real end-to-end sanity check (phone → Telegram voice
message → bot replies) runs on the Mac after this subtask lands. The
runbook's "When It's Silent" troubleshooting table is the user's
self-service path for that smoke. Specifically the table covers:

- `[voice: /path/...]` instead of `[transcription: ...]` →
  `VOICE_INPUT_ENABLED=false` (default).
- First-clip hang → faster-whisper model download (one-time).
- Persistent `failed to process voice message` → API key missing /
  wrong (with the exact log line to look for:
  `voice_input.backend_error`).
- `voice too long — limit 180s` → `MAX_VOICE_DURATION_SECONDS` cap.
- No reply at all → channel-layer issue, not voice-layer.

Each row points the user at the exact env-var name to flip and the
exact log line to grep so they can run the smoke without coming back
to ask.
