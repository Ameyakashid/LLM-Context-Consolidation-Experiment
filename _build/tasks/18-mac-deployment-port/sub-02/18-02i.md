## Summary

Implemented the reversible Windows → macOS data migration for Task 18 / sub-02.
Every runtime data path is already env-var driven (`ADHD_DATA_DIR`,
`TASKWARRIOR_DATA_DIR`, `DASHBOARD_DATA_DIR`, `GOOGLE_OAUTH_CREDENTIALS`,
`GOOGLE_CALENDAR_MCP_TOKEN_PATH`), so **no new helper module was created** —
the research survey confirmed there is no need for `mac_paths.py` and the
description's step 4 is skipped per its own escape clause. The work is:

1. A new CLI at `scripts/migrate_windows_to_mac.py` that copies the
   Windows-side data into `~/Library/Application Support/adhd-assistant/`
   without touching the source.
2. A commented `# === macOS Conventional Paths ===` banner block in
   `.env.example`.
3. A user-facing `workspace/MAC_PATHS.md` shipped via `TEMPLATE_FILES`.
4. 40 new tests — 28 migration script, 8 `.env.example` guards, 5 deploy
   assertions.

Full suite: **1913 passed / 14 skipped** (1873 baseline from sub-01 + 40
new). `mypy --strict` clean on every new file. No `sys.platform` branches
introduced.

## Files created

### `scripts/migrate_windows_to_mac.py` (284 lines)

Argparse CLI modelled on `scripts/migrate_json_to_taskwarrior.py`. Key
pieces:

- `PATH_MAPPING`: frozen tuple of three `PathEntry` dataclasses covering
  `workspace/data/ → <target>/data/`, `workspace/data/taskwarrior/ →
  <target>/taskwarrior/`, and `gcp-oauth.keys.json → <target>/oauth/...`.
- `--dry-run` and `--apply` are a mutually-exclusive pair; absent both,
  dry-run is the default (per description; inverted from Task 16).
- `process_entry()` is pure over its result: returns an `EntryResult`
  with a status string (`copied`, `forced_overwrite`, `would_copy`,
  `skipped_target_exists`, `skipped_source_missing`); no side effects
  beyond the filesystem copy itself.
- Exit codes: `0` clean, `2` missing source, `3` target conflict on a
  fresh target (no prior migration log) without `--force`, `4` permission
  error during copy.
- `write_run_log()` appends a timestamped, parseable block to
  `<target>/migration_windows_to_mac.log` on every `--apply` run.
- Success banner directs the user to uncomment the `.env` Mac block and
  restart.

### `workspace/MAC_PATHS.md` (98 lines)

Four sections per description: "What moves where on Mac" (table), "How
to run the migration" (three commands), "How to roll back" (`rm -rf` +
re-comment), "Troubleshooting" (tilde expansion caveat, missing OAuth
creds, re-doing the syncall pickle, reading the log). Copy-paste
commands throughout; no script literacy required of the reader.

### `tests/test_migrate_windows_to_mac.py` (278 lines)

10 test classes, 28 cases. A single `fake_repo` fixture builds a minimal
layout under `tmp_path` covering every entry in `PATH_MAPPING`; a
`target_base` fixture supplies a sibling tmp directory. Coverage:

- `TestDryRun` — default + explicit flag both leave the target untouched.
- `TestApplyCopy` — data/, taskwarrior/, oauth/ all populated; sha256
  byte-identity on a fixture file.
- `TestIdempotency` — second `--apply` logs `Skip (target non-empty)`,
  returns 0, leaves non-log content hash-stable.
- `TestReversibility` — source-tree sha256 unchanged pre/post `--apply`.
- `TestForceOverwrite` — `--force` removes stale target contents.
- `TestSummaryLog` — header, append across runs, dry-run doesn't write.
- `TestExitCodes` — one case per `0 / 2 / 3 / 4`; permission error uses
  `monkeypatch.setattr(shutil, "copytree", raise_permission)` for
  deterministic, platform-independent simulation (no `chmod 0555`).
- `TestMutuallyExclusiveFlags` — `--apply --dry-run` raises `SystemExit`.
- `TestMissingOptionalSource` — absent `gcp-oauth.keys.json` logs skip
  and continues with exit 0.
- `TestCliSurface` — static grep + `parse_args` assertions for AC #1.

## Key decisions

1. **No new `mac_paths.py` helper.** The research survey (section 1 of
   `18-02r.md`) confirmed every runtime data path is already env-var
   driven. Writing a helper "just in case" would violate YAGNI and
   code-rule AI-1. The description's step 4 allows this explicit
   opt-out: "only if survey in step 1 finds code changes are genuinely
   needed; otherwise skip this step and document zero code changes
   required." Done, and documented.

2. **Mapping table is hard-coded (Approach A).** Matches the description
   verbatim and mirrors Task 16's style. Approach B (derive from
   consumer modules) was rejected — importing from `task_store_factory`
   / `taskwarrior_setup` would pull in pydantic + nanobot + tasklib
   side effects and make the script's tests brittle. Three entries is
   well under the abstraction threshold.

3. **Taskwarrior mapping kept as a separate entry**, not folded into
   `workspace/data/`. Research section 10 risk #2 suggested de-duplicating
   on the grounds that `workspace/data/taskwarrior/` is a descendant of
   `workspace/data/`. That argument doesn't apply here because the two
   entries have *different target paths* — `<target>/data/taskwarrior/`
   vs `<target>/taskwarrior/`. The Mac env-var defaults are
   `ADHD_DATA_DIR=~/.../data` and `TASKWARRIOR_DATA_DIR=~/.../taskwarrior`
   (siblings, not nested). So both copies are required. The duplication
   of bytes is a non-issue: taskwarrior .data files are small, the user
   sets one env var to pick which copy the bot reads from, and the other
   is inert storage. (Documented the tradeoff rather than deviating.)

4. **Exit code 3 fires only on "fresh" non-empty targets.** "Fresh" =
   no `migration_windows_to_mac.log` at the target base. On a second
   `--apply` run the log already exists, so all-skipped becomes the
   idempotent zero-exit path the tests (and AC #2) require. Research
   section 11 flagged ambiguity in the exit-3 semantics; this log-based
   heuristic is the cleanest thing that makes the acceptance test
   matrix consistent ("second run returns 0" vs "first run onto
   populated target returns 3").

5. **`--apply` / `--dry-run` are mutually-exclusive argparse flags.**
   Prevents the subtle footgun of a test fixture copy-pasted from
   Task 16's test suite (which defaults to run-mode) silently landing
   in dry-mode here. The `TestMutuallyExclusiveFlags` case pins the
   behaviour.

6. **Permission-error test uses `monkeypatch.setattr(shutil, "copytree",
   ...)`.** Not `chmod 0555`. Portable across Windows + macOS without
   `sys.platform` gating, which AC #10 explicitly forbids. Research
   section 6 recommended this; followed verbatim.

7. **Tilde-expansion risk documented, not patched.** Research section
   10 risk #1 flagged that `custom_gateway.resolve_data_dir` does *not*
   call `.expanduser()` — a Mac user who uncomments
   `ADHD_DATA_DIR=~/Library/...` without manual expansion would get a
   literal `~` directory created under the CWD. AC #13 forbids editing
   `custom_gateway.py` in this subtask, so we took the scope-clean
   option: `MAC_PATHS.md` "Troubleshooting" + the `.env.example` banner
   both tell the user to replace `~` with `/Users/YOUR_USERNAME`
   manually. Sub-05's live smoke test is where this will surface and
   where the one-line fix should land. **This is the single known
   footgun carried forward from sub-02.**

8. **Append-only log, also written on force path.** `migration_windows_to_mac.log`
   is never truncated; each run appends a timestamped block. The log's
   presence doubles as the "we've migrated here before" marker for the
   exit-3 fresh-target heuristic (decision #4).

## Deviations from the research plan

None of substance. Notable micro-deviations:

- Research section 3 recommended "single `workspace/data/` copytree"
  as simpler; implementation kept `workspace/data/taskwarrior/` as a
  separate entry because the targets differ (decision #3). Tradeoff
  surfaced in the research doc itself ("approach picks (a)… subset
  entries become documented aliases"); here they *aren't* aliases, so
  (a) doesn't fit.
- The permission-error test in research section 6 proposed
  `monkeypatch.setattr(shutil, "copytree", _raise_permission)`. Used
  verbatim, but routed through the stdlib `shutil` module import in the
  test (not via `migration.shutil`), because `from __future__ import
  annotations` plus mypy --strict's `attr-defined` checks require the
  attribute to be explicitly exported by the target module. Same
  behavioural outcome — the script imports `shutil` at module scope and
  calls `shutil.copytree(...)` at call-time, so patching the shutil
  module itself flows through.
