## What shipped

A macOS LaunchAgent stack that turns `.venv/bin/python start.py` into
a supervised, auto-starting per-user service. One command installs,
one uninstalls, one checks status. All three scripts are idempotent.

### 1. `deploy/com.adhdassistant.bot.plist.template` (81 lines)

Static XML plist with five placeholders the installer substitutes:
`${REPO_ROOT}`, `${HOME}`, `${ADHD_LOG_DIR}`, `${NANOBOT_TIMEZONE}`,
`${EXTRA_ENV_ENTRIES}`. Every placeholder is listed in the header
XML comment.

Key values (per description + research §2.2):

- `Label`: `com.adhdassistant.bot`.
- `ProgramArguments`: `[${REPO_ROOT}/.venv/bin/python, ${REPO_ROOT}/start.py]`.
- `WorkingDirectory`: `${REPO_ROOT}`.
- `EnvironmentVariables`: `HOME`, `PATH` (starts with `/opt/homebrew/bin`
  so brew-installed binaries resolve), `LANG=en_US.UTF-8`,
  `ADHD_LOG_DIR`, `NANOBOT_TIMEZONE`, plus the `${EXTRA_ENV_ENTRIES}`
  injection slot for feature flags.
- `StandardOutPath` / `StandardErrorPath`: `${ADHD_LOG_DIR}/bot.out.log`
  and `${ADHD_LOG_DIR}/bot.err.log`.
- `RunAtLoad`: `true` → runs at every login and at `launchctl load`.
- `KeepAlive`: `{SuccessfulExit: false}` (dict form — not bare `<true/>`).
  Relaunches on crash; does NOT relaunch on clean exit from
  `launchctl unload`.
- `ThrottleInterval`: `30` (integer) — protects against tight crash
  loops.
- `ProcessType`: `Interactive`.

### 2. `scripts/install_launchagent.sh` (147 lines)

- `set -euo pipefail` on line 5; `trap … ERR` prints failing line
  number.
- Resolves `REPO_ROOT` via `cd "$(dirname "$0")/.." && pwd`.
- `read_env_value` helper: `grep … | tail | cut || true` — tolerant
  of `.env` missing and tolerant of the key being absent under
  pipefail.
- `expand_tilde` helper: bash 3.2-safe `${value/#\~/$HOME}`. Applied
  to every value extracted from `.env` — launchd does NOT expand
  `~` in plist paths.
- Fallbacks: `ADHD_LOG_DIR` → `$REPO_ROOT/logs`; `NANOBOT_TIMEZONE` →
  `America/New_York`.
- `mkdir -p` both the log dir and `~/Library/LaunchAgents/`.
- Builds `EXTRA_ENV_ENTRIES` from a 13-key whitelist (see §"Env-var
  injection" below). Each kept value is tilde-expanded and XML-escaped
  (`&`, `<`, `>`), then written as `<key>NAME</key><string>VALUE</string>`
  to a temp file.
- Renders the plist via `sed` using `|` as delimiter (because values
  contain `/`). The `${EXTRA_ENV_ENTRIES}` marker line is replaced with
  the temp file via `sed`'s `r` + `d` commands.
- `launchctl unload … 2>/dev/null || true` then `launchctl load -w`.
- Verifies via `launchctl list | grep com.adhdassistant.bot`.
- Prints a banner naming the plist path, log files, status command,
  and uninstall command.

### 3. `scripts/uninstall_launchagent.sh` (23 lines)

- `launchctl unload … 2>/dev/null || true`.
- `rm -f ~/Library/LaunchAgents/com.adhdassistant.bot.plist`.
- Prints a banner reminding the user that data under
  `~/Library/Application Support/adhd-assistant/` is untouched and
  `.venv/bin/python start.py` is the manual fallback.

### 4. `scripts/launchagent_status.sh` (45 lines)

- Reads `ADHD_LOG_DIR` from `.env` (tilde-expands, falls back to
  `$REPO_ROOT/logs`).
- `launchctl list | grep com.adhdassistant.bot`; if absent, prints the
  "not loaded" hint and exits 1.
- Otherwise prints the status line and tails the last 20 lines of
  both log files (`tail -n 20 … 2>/dev/null || echo "(no log yet)"`).
- Exits 0 when PID is numeric OR `LastExitStatus == 0`; non-zero
  otherwise.

### 5. `workspace/LAUNCHAGENT.md` (165 lines)

Sections: "What is a LaunchAgent", "Prerequisites" (calls out the
"no running `python start.py`" requirement and the
`setup_workspace.py` pre-run), "Install", "Uninstall", "Check
status", "Reading logs", "Troubleshooting" (PATH / log-dir
permissions / tight crash loops / `.env` changes not picked up), and
"Rollback" (quick + last-resort Mac → Windows via rsync). Deployed
via `setup_workspace.TEMPLATE_FILES` (a one-line insert keeping the
Mac-deployment docs grouped: `INSTALL_MAC.md`, `MAC_PATHS.md`,
`LAUNCHAGENT.md`, …).

## Key decisions (and why)

### Env-var injection (research §4.11 — Approach 1)

**Decision**: bake a 13-key whitelist from `.env` into the plist's
`EnvironmentVariables` dict at install time.

**Whitelist** (pinned by `TestFeatureFlagWhitelist` in
`tests/test_install_launchagent_script.py`):

- Feature flags: `PULSE_ENGINE_ENABLED`, `DREAM_STATE_ENABLED`,
  `DREAM_STATE_CRON`, `VOICE_AUTO_ENABLED`, `VOICE_DISCO_ENABLED`,
  `GOOGLE_CALENDAR_ENABLED`, `MAGICMIRROR_ENABLED`,
  `MAGICMIRROR_AUTOSTART_ENABLED`, `TASKWARRIOR_ENABLED`,
  `SYNCALL_ENABLED`.
- Path overrides: `ADHD_DATA_DIR`, `DASHBOARD_DATA_DIR`,
  `TASKWARRIOR_DATA_DIR`.

Why Approach 1 (research alternatives: wrapper script, silent
default, patch `start.py`):

- `start.py` does not call `python-dotenv`; it reads `os.environ`
  directly. Under launchd, `os.environ` only holds what the plist's
  `EnvironmentVariables` dict declares — the interactive shell's
  env is not inherited.
- Without injection, every feature flag would silently default to
  false inside the LaunchAgent — Pulse, MagicMirror, syncall,
  Calendar, Taskwarrior, Disco would all go dark. The user would
  not know until they looked at `bot.err.log`.
- A wrapper shell script (Approach 2) would force an AC-literal
  deviation — AC #5 asserts `ProgramArguments` is a 2-element
  `[python, start.py]` list, and the `plistlib`-based test pins
  that shape.
- Patching `start.py` (Approach 4) is forbidden by AC #15.

Anti-leak boundary: **secrets never touch the plist**. Tokens live
in `~/.nanobot/config.json`, which nanobot reads itself —
`OPENROUTER_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_USER_ID` are
never grepped from `.env` by the install script.
`TestFeatureFlagWhitelist.test_no_secret_keys_leaked` grep-asserts
these three names do not appear in the install script source.

Re-run contract: if the user edits `.env` after installing, they
must re-run `bash scripts/install_launchagent.sh` to pick up the
new values. Documented in LAUNCHAGENT.md's Troubleshooting.

### Tilde expansion (research §4.3, §6.3)

Every value read from `.env` passes through `expand_tilde` — bash
parameter expansion `${value/#\~/$HOME}`, which matches
`Path.expanduser()` for a leading `~`. Avoids the sub-02 footgun
where consumers without `.expanduser()` wrote into a literal `~`
directory under the repo. Not using `eval` — `eval` on user-
controlled `.env` content is a code smell.

### Template rendering via `sed` (research §3.1)

`sed` with `|` as delimiter (values contain `/`), one `-e` per
single-line placeholder. For the multi-line `${EXTRA_ENV_ENTRIES}`
insertion, `sed` reads the temp file with `r FILE` at the marker
line and deletes the marker with `d`. Chose `sed` over `envsubst`
(not guaranteed on stock macOS), over bash-only param expansion
(works but mixes styles), and over a Python helper (wrong layer —
install runs before the venv Python is guaranteed resolvable on
PATH).

### No MagicMirror plist (description step 5, research §4.10)

Sub-03's `[magicmirror-autostart-launcher]` index entry confirms
MagicMirror launches **in-process** from `start.py` when
`MAGICMIRROR_AUTOSTART_ENABLED=true`. The description defaults to
"no second plist unless sub-03 deferred autostart". Shipping one
would add dead code. **Not shipped.** `MAGICMIRROR_AUTOSTART_ENABLED`
is on the whitelist so the in-process path gets the env var it
needs.

### `launchctl load -w` / `launchctl unload` (research §2.3)

Description AC #6 greps for `launchctl load` + `launchctl unload`
literally. Ignored the (more modern) `bootstrap`/`bootout` pair —
the old pair is still supported on macOS 14+ and matches the AC.
Research notes this could migrate later if Apple hardens the
deprecation.

## Deviations from the research plan

None that change the set of deliverables. Two minor clarifications:

1. Research §3.3 suggested a shallow `grep ^ADHD_LOG_DIR=`. Under
   `set -euo pipefail`, an unmatched grep trips the pipeline; the
   install script ends each pipeline with `|| true` to tolerate
   the key being absent. Research §3.5 recommends `set -euo pipefail`,
   so both constraints needed to coexist.
2. Research §3.5 suggested a simpler trap (`trap 'echo "... failed
   on line $LINENO" >&2' ERR`). Kept that form across all three
   scripts, even for uninstall/status — the extra line number on
   failure is free and matches the install_mac.sh "readable failure"
   posture.
