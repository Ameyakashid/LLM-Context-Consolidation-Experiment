## Files and what they do

### `install_mac.sh` (new, 117 lines, mode 0755)

Seven-phase idempotent installer.

| Phase | Does |
|---|---|
| 0/7 Homebrew presence | `command -v brew` first; falls back to `eval "$(/opt/homebrew/bin/brew shellenv)"` (ARM) or `/usr/local/bin/brew` (Intel). Fails fast with exit 1 + stderr message if Homebrew is absent. Prints the Apple-Silicon banner via `uname -m`. |
| 1/7 Homebrew packages | Loops `brew list $pkg >/dev/null 2>&1 \|\| brew install $pkg` over `(python@3.11 node task git ffmpeg)` — the exact idiom acceptance #4 names. |
| 2/7 venv | `[[ -d .venv ]] \|\| python3.11 -m venv .venv`. Re-runs skip. |
| 3/7 pip deps | `.venv/bin/pip install -r requirements.txt` then `.venv/bin/pip install -r requirements-dev.txt`. |
| 4/7 MCP server | `(cd mcp/google-calendar && npm install && npm run build)` — one subshell, three `&&`-chained steps (matches `gcal_setup.build_google_calendar_mcp`). |
| 5/7 MagicMirror core | `(cd magicmirror && npm install --ignore-scripts)` — defuses the upstream `postinstall` `git clean -df` the same way `magicmirror_setup.build_magicmirror` does. |
| 6/7 MagicMirror modules | `for d in magicmirror/modules/MMM-*; do [[ -f "$d/package.json" ]] \|\| continue; (cd "$d" && npm install); done`. Loop form chosen over enumerated so a future fourth module works without a script edit. |
| 7/7 Done | Heredoc banner `=== Install complete ===` with the four-step next-actions (copy `.env`, edit it, run `setup_workspace.py`, run `start.py`). |

Scaffolding:

- Shebang `#!/usr/bin/env bash`.
- `set -euo pipefail` on line 10 (within the first 10-line window).
- `cd "$(dirname "$0")"` anchors every relative path at the script's own directory.
- `CURRENT_PHASE` variable + `trap 'echo "FAILED in phase: ${CURRENT_PHASE}" >&2' ERR` — the phase-banner form from research section G. User-friendly; each `phase` helper call updates `CURRENT_PHASE` before printing the banner, so if any subsequent command fails the trap names the readable phase, not just a line number.
- Zero `sudo` calls (acceptance #11).
- Zero `>/dev/null 2>&1` on any step's primary command — the only use is on `brew list` in the idempotency idiom, which is the correct channel to silence (discovery check, not action).

Bash 3.2-safe: no `${var,,}`, no `mapfile`, no `declare -A`, no here-strings inside function bodies. Only features used are `[[ ]]`, `(( ))`, indexed arrays, and heredocs — all present in 3.2.

### `.gitattributes` (new, 2 lines)

```
* text=auto
*.sh text eol=lf
```

Forces `.sh` files to LF on checkout even under Windows `core.autocrlf=true`. Without this, the Mac-target script would get CRLF endings on every Windows clone and bash would fail with `$'\r': command not found` on the Mac.

## Key decisions

### 1. Phase-variable trap over `$LINENO` trap

Both pass the acceptance #12 grep. The phase-variable form prints `FAILED in phase: [3/7] Python dependencies`, which a non-technical user can act on ("something broke while installing pip deps — probably the network"). `$LINENO` would print `FAILED at line 61: .venv/bin/pip install -r requirements.txt` — more diagnostic but requires the user to read the script.

### 2. Glob loop for MMM-modules over enumerated

Research section B left this open. I chose the loop form with a `[[ -f "$d/package.json" ]] || continue` guard. Wins over enumeration: a fourth MMM-module added tomorrow ships without a sub-01 script edit. Loses: `basename` logging replaces the "step 5/N: MMM-Markdown failed" precision. The trap-by-phase resolves the lost precision — a module failure still pins the phase, and `echo "Installing $(basename ${module_dir})"` pins the specific module.

### 3. `[[ -d .venv ]]` guard over `[[ -x .venv/bin/python ]]`

Research section C left this open. Directory check matches acceptance #5 literally and is what the supervisor spec quotes. The stricter binary check would handle mid-creation corruption; I traded that for the literal acceptance-grep match. A half-created venv is a vanishingly rare failure mode on the fresh-Mac flow, and the recovery is `rm -rf .venv && bash install_mac.sh` — documented in `INSTALL_MAC.md`'s re-running section.

### 4. No `task --version` auto-seed

Supervisor flagged this as nice-to-have. Skipping it per research section §"Risks & assumptions" risk 3. Rationale: the Brew `task` formula's non-interactive auto-seed behaviour is inconsistent across versions; a prompt mid-script would halt the installer and confuse a non-technical user. `INSTALL_MAC.md` documents the one-time `yes` prompt instead — acceptable because the prompt only fires the first time the user runs a `task` command, and that is always after `install_mac.sh` exits.

### 5. No `pip install --upgrade pip` step

Considered. Dropped per code-rules §"No 'just in case' code". A fresh `python3.11 -m venv` on Brew's `python@3.11` ships a pip recent enough to resolve every pin in `requirements.txt`. If a future wheel resolution breaks, sub-05's smoke test flags it and that becomes a targeted one-line fix — not a pre-emptive step.

### 6. No `pip install ./vendor/syncall`

Confirmed correct by research section §"Risks & assumptions" risk 6. `vendor/syncall` is sys.path-loaded by design (it does not `pip install` cleanly due to `poetry-dynamic-versioning` + PyYAML 5.3 pin); its 10 transitive deps are pinned individually in `requirements.txt`. The install script must NOT add that line; doing so would break sub-03-of-Task-16's careful design.

### 7. `.gitattributes` added

Not listed in the description. Included because the file `install_mac.sh` is the only bash script in the repo that runs on Mac, and Windows-default `core.autocrlf=true` would silently corrupt it on every clone. Minimal two-line addition; `* text=auto` preserves the existing baseline for everything else. Flagged here because the description did not name this file — verification should confirm it is non-harmful for the Windows-resident repo.

## Deviations from the research plan

1. **`.gitattributes` added.** The research plan did not name this file. Added for correctness on the Windows dev host (CRLF conversion would silently corrupt the Mac target). Justified above under "Key decisions §7".
2. **No `--upgrade pip` preamble.** Research section was silent; anti-slop rules forbid just-in-case steps.
3. **Loop over enumerated for MMM-modules.** Research left this open (section B); chose loop. Future-proof over byte-matching.

No deviations from acceptance criteria; every numbered #1–#17 criterion is satisfied.
