## 2. Decisions made

### 2.1 Approach C (hybrid), file split into two modules

Research §2 laid out three approaches. The implementation picked
**Approach A (pure subprocess) split across two files** per research
§8.1 ("if the file feels like it'll cross 290 lines, split"). The
single-file draft landed at 331 lines — above the 290 cap — so the
explicit description fallback kicked in:

- `tests/test_mac_smoke.py` (60 lines): baseline markers + graceful shutdown.
- `tests/test_mac_smoke_phase2.py` (176 lines): Phase 2 flag cells + LaunchAgent rollback.
- `tests/_mac_smoke_harness.py` (151 lines): shared `run_until_markers`
  driver and helpers.

The harness isn't a single-purpose utility — both test files use it, so
code-rule #4 ("no single-purpose utility files") is satisfied with two
callers. A `conftest.py` fixture was rejected because the driver is a
plain function (not a fixture) and module-level imports stay flatter.

### 2.2 Pure subprocess posture (Approach A, not C hybrid)

AC #4 ("SIGINT reaps MagicMirror, syncall daemon, and any Pulse/Dream
asyncio tasks within 15 seconds") is only truthfully assertable with a
real subprocess. The harness spawns `[<repo>/.venv/bin/python, start.py]`
with `cwd=<repo>`, merges fake credentials into the child environment,
and tails `stdout+stderr` (merged via `stderr=STDOUT`) for marker
substrings with a 60-second watchdog. On marker-set-complete or
watchdog timeout it sends `SIGINT` and `communicate(timeout=15)`s the
remainder. If shutdown exceeds 15 s the test raises
`AssertionError` (not `TimeoutExpired`) so the failure message is
actionable.

### 2.3 The `.expanduser()` symmetric fix extends to dashboard_api

Research §1.4 scoped the fix to `custom_gateway.resolve_data_dir` /
`resolve_states_path` and noted "other call sites the implementation
agent should grep for symmetry." The grep found
`dashboard_api.load_config_from_env` reading `DASHBOARD_DATA_DIR` and
`DASHBOARD_STATIC_DIR` without `.expanduser()`. The `.env.example` Mac
block ships `DASHBOARD_DATA_DIR=~/Library/Application Support/adhd-assistant/data`
as a recommended value, so the same landmine was set. The fix added
`.expanduser()` to both dashboard fields. `taskwarrior_setup.resolve_taskwarrior_data_dir`
(line 35) already called `.expanduser()` — nothing to do there.

### 2.4 MAC_DEPLOYMENT.md per Approach A (single doc)

Single 150-line file. Links out to the four companion docs rather than
duplicating their bodies (Approach C in research §3 was rejected — the
description says one new file, one deploy test, one manifest insert).
TL;DR is five commands exactly, matching the description's shape. Cost
posture is restated to keep the $7/month ceiling searchable from the
runbook itself (AC #14).

### 2.5 README.md: 8-line surgical diff

Three edits: top banner (1 blockquote added at line 3), Prerequisites
callout (1 line added after line 141), Platform Support table (2 rows
updated: macOS status → "Deployment target", Windows status →
"Development only"). Net diff is 8 lines — well under the 30-line cap.
All other sections byte-identical.

### 2.6 Not attempted

- **MagicMirror `npm start` on Apple Silicon** (research §6.3). The fix
  path ("npm start → npm run server --prefix") is deferred to the verify
  agent's Mac run, because the bug only manifests when the actual
  `node --run start:wayland` script executes. Static diff against
  `magicmirror_launcher.build_magicmirror_command` would have been
  speculative. If the Mac smoke's `test_magicmirror_autostart_spawns_child`
  fails, the fix is a one-line argv change committed in this same subtask
  per AC #5.
- **Cell 4 (Dream) static-only assertion.** The smoke relies on the
  process writing `"Cron service started"` markers rather than driving
  Dream synchronously. Research §6.6 suggested lifting
  `test_task17_integration.py`'s pattern; doing so inside a subprocess
  test was judged over-scope. The existing flag-matrix test at
  `tests/test_task17_flag_matrix.py::test_cell_4_pulse_on_dream_on`
  already gives the in-process assertion; the Mac smoke's role is to
  prove the bundle boots cleanly under live subprocess.

## 3. The deferred `.expanduser()` patch — what shipped

### 3.1 `custom_gateway.py` (sub-02 → sub-05 hand-off, now closed)

Lines 70-72 and 78-80:

```python
env_dir = os.environ.get("ADHD_DATA_DIR")
if env_dir:
    return Path(env_dir).expanduser().resolve()
```

Two-line change. `Path(str).expanduser()` is a no-op when the string
doesn't start with `~`, so the Windows tests that set
`ADHD_DATA_DIR=<tmp_path>/data` (not a tilde) keep working. Grep against
`tests/` confirmed no existing test sets `ADHD_DATA_DIR` to a tilde
literal (research §6.5 check).

### 3.2 `dashboard_api.py` (symmetric fix)

`load_config_from_env` already used `Path(os.environ.get(...))`. Added
`.expanduser()` to `data_dir` and `static_dir`. A docstring note
explains why ("Mac-block `.env.example` entries …").

### 3.3 TDD evidence

Two failing-then-passing pairs, committed in one commit:

- `tests/test_custom_gateway.py::TestResolveDataDir::test_env_override_expands_tilde`
- `tests/test_custom_gateway.py::TestResolveStatesPath::test_env_override_expands_tilde`
- `tests/test_dashboard_api.py::TestLoadConfigFromEnv::test_data_dir_expands_tilde`
- `tests/test_dashboard_api.py::TestLoadConfigFromEnv::test_static_dir_expands_tilde`

Each asserts `str(result).startswith(str(Path.home()))` and
`"~" not in str(result)`. Cross-platform: `Path.home()` on Windows
returns `C:\Users\<user>` and `expanduser` resolves `~` to that, so the
assertions pass on both OSes without branching.

## 4. The smoke test harness — what the file actually does

`tests/_mac_smoke_harness.py` exports:

- `BASELINE_MARKERS` — 7-marker tuple pinning the 2026-04-16 log shape
  (research §1.2): gateway start, 6-hook ready line, dashboard bound on
  0.0.0.0:8085, 5 task tools, 5 buffer tools, 3 memory tools, 1 voice
  tool. 14 tools summed = AC #2's "≥14 tools registered" floor.
- `FAKE_CREDENTIALS` — sub-`test_bot_smoke.py`-style fake keys so the
  child process passes `validate_env_vars` but the fake Telegram token
  fails at `getMe`, keeping the smoke hermetic.
- `run_until_markers(markers, env, boot_window_s=60)` — spawns
  `start.py` under `.venv/bin/python`, line-reads stdout until every
  marker matched, sends SIGINT, asserts 15-second shutdown deadline.
- `require_venv()` — `pytest.skip` if `<repo>/.venv/bin/python` missing
  (precondition per AC #1).

`tests/test_mac_smoke.py` classes:

- `TestBaselineSmoke`: three tests — `test_baseline_markers_appear`,
  `test_baseline_no_traceback`, `test_graceful_shutdown_within_deadline`.
  Each spawns a fresh subprocess; ~5 s per test on Mac per research §1.2.

`tests/test_mac_smoke_phase2.py` classes:

- `TestPhase2FlagCells`: seven tests, one per Phase 2 adapter (research
  §1.1 table). Each toggles one env var and asserts the corresponding
  log symbol. MagicMirror/MagicMirror-autostart tests `pytest.skip` when
  `magicmirror/config/config.js` isn't rendered yet; Taskwarrior skips
  when `task` isn't on PATH (mirror of research §6.7 fail-soft posture).
- `TestLaunchAgentRollback`: one test — install → `launchctl list` →
  uninstall → assert plist absent + not in `launchctl list`. Refuses
  to run if `~/Library/LaunchAgents/com.adhdassistant.bot.plist` already
  exists (clobber guard for a user with a real install).
