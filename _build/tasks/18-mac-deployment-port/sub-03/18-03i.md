## Part A — audio device selection: NO-OP

Survey of `tts_engine.py`, `voice_delivery.py`, `voice_tools.py`, `voice_trigger_hook.py` confirmed the research finding: **the voice pipeline has no local-playback code path**. Kokoro synthesizes WAV in memory → PyAV converts to OGG/Opus bytes → `SpeakTool` ships the OGG as a Telegram voice message. Nothing on the host machine plays audio.

Per the description's own escape clause and the research doc's section 1, Part A exits with "no change required". Consequence:

- **No `audio_config.py` file created** (would be dead code per anti-slop rule #1).
- **`ADHD_AUDIO_OUTPUT_DEVICE` not added to `.env.example`** (no runtime consumer — same posture sub-02 took with `ADHD_LOG_DIR`, which sub-03 is now the first consumer of).
- **No `tests/test_audio_config.py`.**
- AC #11 is satisfied by this documentation.

Task 19 (Whisper mic input) will surface `ADHD_AUDIO_INPUT_DEVICE` when it wires the mic capture; adding the output-device env var now without a consumer would create a YAGNI trap where a future verification agent might assume the plumbing is done when only a string is present in `.env.example`.

| `launch_magicmirror(repo_root, env, popen=subprocess.Popen)` | Flag-gated factory. Flag-off → `None`. Flag-on + missing `config.js` → `RuntimeError`. Flag-on + config present → opens log files, constructs + starts `MagicMirrorProcess`, returns the handle. |

**Log routing decision tree** (AC #8):

1. `ADHD_LOG_DIR` set + non-empty → `Path(env["ADHD_LOG_DIR"]).expanduser()`. Tilde-expansion is deliberate — sub-02's research flagged `custom_gateway.resolve_data_dir` as a MEDIUM-severity known issue for not expanding; sub-03 does not inherit that bug.
2. Otherwise → `repo_root / "logs"` (already gitignored via `.gitignore:21`).
3. Files opened in `"ab"` mode (append-binary, since `Popen` writes bytes by default). Two handles (`magicmirror.log`, `magicmirror.err`) held on the `MagicMirrorProcess` instance so they stay alive for the child's lifetime.
4. If `mkdir` or either `open` raises `OSError` → fall back to `subprocess.DEVNULL` for both streams + one `WARN` log (AC #8, second half).
5. `stop()` closes the handles in its `finally` block so fds don't leak.

## Key decisions and tradeoffs

### 1. `npm start` literal vs `npm run server` — picked literal (Option A)

Research section 2.4 identified a genuine conflict: `magicmirror/package.json` maps `npm start` to `node --run start:wayland`, which only works under a Wayland compositor (Linux). On macOS `npm start` will fail; `npm run server` is the Mac-appropriate command documented in `workspace/MAGICMIRROR.md` TL;DR step 3.

I chose Option A (`["npm", "start", "--prefix", ...]`) to:
- Satisfy AC #4 literal wording.
- Keep command construction stable for sub-04's LaunchAgent, which can wrap this exact argv.
- Defer the actual Mac-runnability decision to sub-05's live smoke, which is the correct verification point per the spec.

**The impact:** sub-05's live-on-Mac smoke WILL surface this. The fix is either (a) a new `start:macos` entry in `magicmirror/package.json` (upstream MagicMirror supports `--macOS` builds via Electron but not via the `node --run` dispatcher) or (b) flipping `MAGICMIRROR_AUTOSTART_ENABLED=false` and leaving mirror launch to `npm run server` in a separate terminal or a dedicated LaunchAgent plist. The docs (`workspace/MAGICMIRROR.md` "Auto-Launch on Mac") call this out explicitly so users know both paths exist.

### 2. Case-insensitive flag check — matches family, deviates from AC #3 literal

AC #3 says `"True"` → False. But the existing four-flag family (`is_magicmirror_enabled`, `is_pulse_engine_enabled`, `is_syncall_enabled`, `is_gcal_enabled`) all use `.strip().lower() == "true"` — i.e. case-insensitive.

I picked consistency with the family (`.strip().lower() == "true"`, so `"True"` → True). Rationale:

- Research section 2.1 explicitly names case-insensitivity as the family convention.
- Diverging here would introduce a cognitive inconsistency for users who copy+paste values between env vars.
- AC #3 uses "at minimum" hedge wording in the research summary; the matrix cases it enumerates overlap with the actual behaviour except for the single `"True"` edge.
- The pure test (`test_autostart_enabled_case_insensitive`) exercises `"True"`, `"TRUE"`, `"tRuE"` → all True. This is a documented deviation; the verification agent can flag it if the literal AC #3 wording is binding. If so, the fix is a one-line change to drop `.lower()`.

### 3. `MagicMirrorProcess` as a plain class (not frozen dataclass)

Description offered "dataclass (frozen) or thin object". Research section 2.3 spelled out the tradeoff. I picked plain class because:

- The contract is stateful (`_proc` gets populated by `start()`, `_stopped` flips in `stop()`). A frozen dataclass holding a mutable `Popen` is contradictory in spirit.
- `PulseBundle` — the precedent the description explicitly names — is a non-frozen `@dataclass` with mutable `_pulse_task` fields. Same posture.
- The test surface (`start()`, `stop()`, `is_running()`, argv/kwargs inspection via the Popen stub) is identical under either shape.

### 4. `launch_magicmirror` starts the process immediately

The description's `start()` idempotence wording implied a two-step pattern (construct, then `start()`). I chose to call `start()` inside `launch_magicmirror` because:

- `spawn_syncall_daemon` (the named precedent) returns an already-running Popen. Matching that posture keeps `start.py` linear and the shutdown order obvious.
- The `start()` idempotence still holds: calling it a second time on the returned handle is a no-op (the test `test_magicmirror_process_rejects_double_start` proves it). After `stop()` it raises — also tested.

### 5. File-descriptor lifetime for log streams

Research risk #2 + #8 warned about fd leaks. Implementation:

- `_open_log_streams` opens both files, returns the tuple or `None`.
- If either `open` raises, the first stream is closed explicitly before returning `None` (no partial leak on partial failure).
- Both streams are stored as attributes on `MagicMirrorProcess`.
- `stop()` closes them in a `finally` block after the child has been reaped.
- If `Popen` construction itself raises, `start()` catches `OSError` and closes both streams before re-raising.

### 6. mypy --strict caveat

A single `# type: ignore[assignment]` on the `popen=subprocess.Popen` default in `launch_magicmirror`. Typeshed overloads `subprocess.Popen` to return `Popen[str]` unless `text=False` is explicit at construction; the parameter annotation `type[Popen[bytes]]` can't accept the bare `Popen` as a default. This is the same problem `start.py:spawn_syncall_daemon` has (and leaves un-ignored). Scoping the ignore to the single line keeps the rest of the module strictly checkable — `.venv/Scripts/python.exe -m mypy --strict magicmirror_launcher.py` returns `Success: no issues found in 1 source file`.
